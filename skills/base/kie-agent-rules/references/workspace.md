# 工作空间落点

开发和测试放在 `~/kie-ws` 下，按任务组织工作空间。任务根目录是本次任务的工作空间，任务涉及的各个仓库直接放在其中。用户默认在任务根目录启动会话。

| 用途 | 路径 |
| --- | --- |
| 无工单编号的任务根目录 | `~/kie-ws/<任务简述>/` |
| 有 SWE 工单编号的任务根目录 | `~/kie-ws/swe-<编号>-<任务简述>/` |
| 任务涉及的仓库 | `<任务根目录>/<仓库名>/` |
| 方案、设计与设备信息 | 任务根目录下的 `solution.md`、`design.md`、`devices.md` |
| 任务临时文件 | `<任务根目录>/.tmp/`，按具体活动建立子目录 |
| 测试文件与验收报告 | `.tmp/test/<n>/`，报告为 `test-report-n.md` |
| 调研过程文件与报告 | `.tmp/<调研简述>/` |
| 修复记录 | `.tmp/fix/fix-n.md` |
| 评审与修复评论 | `.tmp/comment/comment-review-n.md`、`comment-fix-n.md` |
| 仅生成文档的临时产物 | `.tmp/docs-tmp/` |
| 评估与调试沙箱 | `<任务根目录>/.tmp/test/`，按具体评估或调试任务建立子目录 |

- `<任务简述>` 根据本次工作内容命名，调研、开发等任务都使用同一规则，不自动添加 `spike-` 等任务类型前缀。
- 从用户请求、工单字段、链接和已有任务上下文识别本任务的 `SWE-<编号>`，识别时不区分大小写。出现本任务的编号即按工单命名，保留 `swe-` 和数字组成的完整编号。没有编号时直接使用任务简述，不要求用户补单号。
- 关联缺陷或依赖工单的编号不替换当前任务编号。上下文出现多个编号时，优先使用用户明确指定的主任务编号。无法确定主任务时先询问，不任意选择。
- 跨仓改动的仓库放在同一个任务根目录，任务内的文档和记录按上表组织。复用用户已打开或指定的任务目录，不因识别到编号自行重命名或迁移已有目录。
- 调研时已克隆的仓库直接复用。开始开发时在该仓库创建或切换到本任务的分支，无需另外准备源仓库或工作区。创建与切换前检查现有分支及未提交改动，避免覆盖其他工作。
- `.tmp/` 下按活动归类，该活动的脚本、下载产物、日志和报告放在同一目录。测试轮次 `n` 在 `.tmp/test/` 下取已有最大编号加一，从 1 开始。`fix/` 与 `comment/` 各自编号，保留既有记录。
- 仅生成文档时统一使用 `.tmp/docs-tmp/`。已经明确为任务交付物的 `solution.md`、`design.md`、`devices.md` 保留在任务根目录。没有工单时也按内容建立任务目录，中间产物归入该任务。
- 任务文档与临时文件不放进代码仓库，`~/kie-ws` 根目录不落单个文件。

## 工作目录恢复

- 开始任务时记录用户打开或指定的任务根目录，不能把进入仓库后的 Git 根目录当作任务根目录。用户指定的位置与默认布局不同时使用指定位置。
- 执行仓库命令时优先传入工具的工作目录参数，或使用 `git -C <仓库路径>`，保持会话工作目录位于任务根目录。
- 如果操作改变了持久终端或会话的工作目录，仓库修改与测试结束后恢复到记录的任务根目录，并通过该会话的目录状态或 `pwd` 确认。命令失败、中断或交还用户处理前也恢复。
- 独立子进程中的 `cd` 不会改变会话工作目录，不能用子进程的 `pwd` 声称已恢复会话。工具无法修改会话目录时，后续命令显式使用任务根目录作为工作目录，并说明会话目录无法由当前工具更改。
