## 用词的例子与边界

- 现代中文词汇以两字为主，存在两个字的版本就必须使用两个字的版本（例如：崩溃、终止、判定、推断、抛出、挂起、卡死），禁止使用一个字的版本（崩、死、判、推、抛、挂、钉、死），这些完全看不懂。
- 禁止生造名词。例如“两个字的版本”也不允许被缩减为“两字版本”，“单个字的版本”也不允许被缩减为“单字版本”。
- 描述具体操作时使用完整的动宾结构，说明动作与对象，禁止使用自造的缩略说法，例如：把“用新版本动态库替换 `_vllm_fa3_C.abi3.so` 共享库文件”说成“换库”。
- 日常说明使用简单、完整、含义明确的词语，避免含义模糊的行业黑话。

技术术语的使用范围：

- 技术说明、文档和注释允许使用项目 `AGENTS.md` 及其引用的开发约定中的完整术语。例如“契约”用于接口、事件或输出行为约定，“散落”用于代码分布，“拆分”用于模块组织，“栈”用于具体数据结构或运行时机制。
- “错误落地”用于项目规定的错误渲染与退出码处理，“对齐”用于具有明确对象的格式、版本或行为一致性要求。日常说明优先使用“处理错误”“保持一致”等具体表达。
- 日常说明避免使用“技术栈”“模型栈”“落地”“钉死”“打死”等宽泛或比喻性表达，直接说明所用技术、模型、具体动作与对象。
- 保留项目中的完整技术词语，例如“死锁”“偏移”“硬件”“软件”“虚拟资源”。禁止将完整词语缩短为含义不清的单个字。
- 代码 identifier、文件路径、命令和必要的原文引用保持原样。其余自然语言继续遵守完整用词和清楚表达的要求。

## 项目专属条款

Wuji CLI 的错误处理：默认使用 `anyhow::Result` 和 `?` 传播错误，预期内错误使用 `anyhow!` 或 `bail!` 提供可读信息。命令通过 `Cli → run_cli() → match → command::run → render_error` 处理，由 `run_cli()` 按输出模式渲染错误并统一返回退出码。子命令内部不调用 `process::exit`，项目开发约定明确规定的特殊路径按其规则执行。

Wuji CLI 的批量操作：`upgrade --all` 等批量命令串行处理设备，单台失败后继续处理下一台，最终汇总失败。至少一台失败时返回退出码 `1`。
