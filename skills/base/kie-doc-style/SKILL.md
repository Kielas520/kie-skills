# 项目文档文风规范

检查与生成项目文档正文的文风。中英文都适用，规则全集在 [references/style-guide.md](references/style-guide.md)，中文冗余词对照在 [references/zh-colloquial-lexicon.md](references/zh-colloquial-lexicon.md)。

## 适用范围

- 适用：写进文件或交给他人发布的文档正文，包括 README、设计文档、PR 描述、release notes、周报、报告、邮件、博客、对外公告。
- 不适用：agent 自己的对话回复（归 `kie-agent-rules`）、代码本身、README 与 CHANGELOG 的固定结构模板。

## 子能力

| 子能力 | 用户说法 | 产出 |
| --- | --- | --- |
| 检查 | 「检查文风」「看看写得怎么样」「查标点」 | 一份检查报告，不改文件 |
| 生成与改写 | 「润色」「改得简洁点」「帮我写」「生成 release notes」 | 按规范写成的正文 |

检查完成后要不要按报告修改文件，由用户决定：报告末尾问一句「发现 N 个问题，要按报告修改吗」，用户同意后才改。

### 检查

1. 读 `references/style-guide.md`；内容含中文时再读 `references/zh-colloquial-lexicon.md`。
2. 判定语言（英文、中文、中英混排），按下方「检查类别」逐项检查。
3. 每条问题都过一遍「判断原则」，不满足的不报。
4. 按下面的格式输出报告。问题用原文片段定位，不用行号：行号会随版本变化，原文片段可以跨版本搜索。

```markdown
## 文风检查报告

**范围：** <文件路径，或「粘贴文本」>
**语言：** <English / 中文 / 中英混排>
**问题数：** <N>

| 类别 | 当前文本 | 建议修改 |
| --- | --- | --- |
| 冗余词 | `对文档进行了更新` | `更新了文档` |
```

### 生成与改写

1. 读同样的规则文件。
2. 产出位置：用户指定了文件就写进该文件，改写已有文件就改原文件；用户没有指定时，正文贴在回复里，不自行新建文件。
3. 交付前按「检查类别」自查一遍。

## 判断原则

检查类别里的规则与下面四条冲突时，以下面四条为准。

1. 先确定读者再套规则：对外文档（README、release notes、公开 PR）不写内部代号、未定稿状态、内部工具名、生产流程；内部文档（设计文档、代码评审）可以写。
2. 改之前问价值：改动要让文本明显更清楚、更准确。只删一个词、没有结构上的收益，就不改。
3. 删之前问语义：要删的词如果承载语义，删了意思会变，就不删。
4. 规则服务于可读性，不服务于字数。拿不准就保持原样。

## 例外

以下内容不报问题，也不修改：

- 警示语气词（如「请勿」）：有意保留的强度表达。
- 发布记录：以结构为主，语气从宽，礼貌用语不必删。
- 约定俗成的引用语与指引套话。
- 代码标识符、命令、URL、文件名：按原文保留，不改写也不翻译。
- 引文与他人原文。

## Gotchas

- 中英混排的文档按语言分别套用对应规则。
- 「你」与「您」：团队没有统一约定时不强制改成某一种，全文保持一致即可。
