# 问题复现与定位现在怎么做的（素材）

## 背景

- 排查的是本机跑得起来的项目，复现与定位都在本地完成，动作不落到远端。
- 记录写在 `docs/repro/<日期>-<现象短名>.md`，一个现象一个文件。
- 谁写：当次排查的人自己写，别人照着记录能再走一遍。

## 现在实际怎么做

1. 先拿最小复现：把现象压到一条命令能跑出来的程度，压不出来就继续删输入。
2. 失败输出留原始文本，不摘录：`cargo test <用例名> -- --nocapture 2>&1 | tee docs/repro/<文件>.log`
3. 找引入点用二分：`git bisect start <坏提交> <好提交>`，每步用同一条复现命令判好坏。
4. 追一条符号的历史：`git log -S '<符号>' --oneline -- <路径>`
5. 判断是配置还是代码：同一条命令换默认配置再跑一次，两次结果并排记下来。

## 记录里的写法

- 标题写现象，不写猜测：`## 空输入时解析崩溃`，不写 `## 空指针排查`
- 固定三节：`## 现象`、`## 定位`、`## 结论`；结论没有定下来时写 `## 结论（待定）`，不要留空节
- 命令给可直接粘贴的原文，带工作目录
- 每条结论后面挂证据：命令、输出片段、提交号

## 判断条件（踩过的坑）

- 复现不出来时先固定环境（版本、配置、输入文件），不靠多跑几次碰运气
- 二分时每一步都要重新构建，跳过构建会把引入点定到别处
- 现象与仓库里现有记录重复时，在旧文件里补一条「复现于 <版本>」，不新开文件
- 只在别的机器上出现的问题不进这套记录，改在工单里跟

## 不写什么

- 不写「已修复」这类跟代码状态绑定的结论，结论只写定位到的原因
- 不贴截图，贴文本
- 不用「大概」「可能」这类含糊说法
