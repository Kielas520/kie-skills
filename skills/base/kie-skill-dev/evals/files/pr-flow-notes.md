# 改动到合并这套流程（素材）

本文件是写技能用的素材，描述流程本身，命令只写本地跑得动的那部分。

## 链路

1. 从最新主干开分支：`git switch -c <类型>/<单号>/<英文梗概> origin/main`
2. 本地提交，一个提交一件事，提交信息按 `<类型>: <中文说明>` 写。
3. 把分支推上去，然后在平台上开 PR，body 按模板写清改动、验证方式与遗留。
4. PR 建好后 CI 自动跑，没过就在本机修到过为止，不等人催。
5. 评审意见逐条处理，处理完在对应讨论串回复，改完重新推。
6. 合入主干用 squash，由有合并权限的人执行，合完删掉远端分支。
7. 合完在群里发一条通知：PR 链接、单号、影响范围。

## 判断条件（踩过的坑）

- 分支名里的单号必填；个人小改动写 `chore/<梗概>`，不带单号。
- 格式或 lint 没过时先在本机跑一遍修复脚本，不把失败直接推上去。
- 评审意见与项目约定冲突时，在讨论串里说明理由，不闷着改。
- 一个 PR 只放一件事，两件事就拆两个 PR，第二个基于第一个的分支。
- 合并在评审通过之后做，评审没有明确结论时不合并。

## 不写什么

- 提交信息里不写「临时」「再改一下」这类过程说明。
- PR body 不贴大段日志，日志给附件路径。
