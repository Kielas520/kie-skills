# 发布说明草稿

把一段提交范围整理成人能读的发布说明，草稿先给用户看。

## 步骤

1. 取上一个 tag 到 HEAD 之间的提交（`git log --no-merges <tag>..HEAD`），先读出这次改动的范围。
2. 每条改动写成一句使用者能感知的话，说清变了什么，不抄提交标题。
3. 按模块分组，组内按改动的先后排列。
4. 草稿交用户确认之后才写进文件。

## 判定条件

- 提交超过 500 行改动才需要单独成节。

## Gotchas

- 合并提交与只改文档的提交不进草稿。
- 用户给出的范围是标签区间时按标签取，不按日期猜。
