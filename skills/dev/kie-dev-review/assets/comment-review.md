## 填写要求

1. 本地分支只保留标题、评审对象、范围和「建议」；没有问题也如实写明检查范围和剩余风险。
2. PR 保留「PR body」和「内联评论」，无对应内容时写「无」，不保留「建议」节。PR body 承载整体意见、跨文件问题和不适合行内评论的内容；行内评论每条包含路径、head 行号和原样发送的正文。元信息注明 PR 链接及 head SHA。
3. 行内位置须在 head 的 diff hunk 中；无法定位到有效行的意见写入 PR body。同一问题出现多处时合并，列明其他位置。
4. 评论说明问题、依据、影响和建议；使用四反引号包裹正文，正文内代码块用三个反引号。不要写无法确认的问题作为事实，也不发送评论。
