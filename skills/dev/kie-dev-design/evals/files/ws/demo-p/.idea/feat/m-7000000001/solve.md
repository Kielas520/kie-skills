# CLI 日志导出 选定方案

> 本文件由 `kie-dev-solution` 在用户拍板后产出，只记录已确认的方向，供 `kie-dev-design` 写 `design.md` 使用。
> 取舍过程、全部候选方案与未选原因留在同目录的 `solution.md`，本文件不重复抄录。
> 落点：`~/kie-ws/demo-p/.idea/feat/m-7000000001/solve.md`。

## 要实现的功能

把设备端日志导出成可与同事交换的单个文件，验收条件是导出文件能被重新读回并逐条核对。

## 项目现状

`log export` 子命令只把日志打印到标准输出，没有落盘与打包能力；仓库里已有一个只读的解析模块可复用。

## 选定方案：全量读进内存再一次性写

`log export` 增加输出路径参数。给出路径时，先把全部日志经现有只读解析模块读出、格式化为内存缓冲，缓冲构造完成后一次性写入目标文件；任何步骤失败都不在目标路径留下内容。未给出路径时保持现在打印到标准输出的行为。

需要新增的部分：`src/cli/export.rs` 的 `export_buffered`，以及内存缓冲上限的判定与超限报错。现有只读解析模块只被调用，不被修改。

## 取舍

| 未选方案 | 不选的原因 |
| --- | --- |
| 流式写入 | 写到一半失败会留下半截文件，与验收要求的可核对文件冲突 |
| 调用外部打包工具 | 依赖系统上外部工具存在，跨平台行为不一致，临时文件清理与错误码传递复杂 |

## 风险与前置条件

- 超大日志占用内存高：必须设上限，超出上限时报错且不落盘。
