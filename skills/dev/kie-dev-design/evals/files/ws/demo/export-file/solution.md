# CLI 日志导出 选型文档

## 要实现的功能

把设备端日志导出成可与同事交换的单个文件，验收条件是导出文件能被重新读回并逐条核对。

## 项目现状

`log export` 子命令调用只读解析模块读出设备的全部日志记录，逐条格式化后打印到标准输出；数据从设备日志目录经解析模块进入内存，再流向标准输出。本次改动碰到的是输出这一环。

## 方案一：流式写入（风险 低）

边读边写目标文件；写到一半失败会留下半截文件，与验收要求的可核对文件冲突。

## 方案二：全量读进内存再一次性写（风险 低）（已选定）

`log export` 增加输出路径参数。给出路径时，先把全部日志经现有只读解析模块读出、格式化为内存缓冲，缓冲构造完成后一次性写入目标文件；任何步骤失败都不在目标路径留下内容。未给出路径时保持现在打印到标准输出的行为。

需要新增 `src/cli/export.rs` 的 `export_buffered`，以及内存缓冲上限的判定与超限报错。现有只读解析模块只被调用，不被修改。

## 方案三：调用外部打包工具（风险 中）

依赖系统上的外部工具，跨平台行为不一致，临时文件清理与错误码传递复杂。

## 拍板方向

选定全量读进内存再一次性写；必须设置内存缓冲上限，超出上限时报错且不落盘。流式写入可能留下半截文件；外部打包工具依赖系统环境且跨平台行为不一致，因此均不选。
