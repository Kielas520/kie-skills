# 开发前的调研与方案选型

把用户提出的功能调研清楚，产出选型文档交用户选定。本技能不改业务代码。工作目录为 `~/kie-ws/<仓库名>/<name>/`，`<name>` 是根据本次工作内容取的简短梗概；源仓库位于 `~/kie-ws/<仓库名>/source/`，分支代码位于工作目录下的工单编号目录，无工单时为 `branch_source/`。

## 子能力

| 子能力 | 产出 | 何时做 |
| --- | --- | --- |
| 准备源仓库 | 源仓库现状报告；用户同意后克隆或同步 main | 调研要读已有工程的代码时 |
| 调研 | 调研结论，写进 `solution.md` 的项目现状与各方案 | 用户要求出方案时 |
| 写选型文档 | `<name>/solution.md`：项目现状与全部候选方案，不带选定标记 | 用户要求出方案文档时 |
| 记录拍板 | 在 `solution.md` 标注选中方案并记录拍板方向 | 用户拍板选定某个方案时 |

每个子能力做不做、按什么顺序做由用户决定。已有拍板记录不等于对本次写入的授权：用户拿已选定的文档回来提意见，或问「要不要改」时，先给改动清单等回应，不因为「已经拍过板」就直接改文档或重建文档。

## 准备源仓库

先只读取现状并报告给用户，克隆、切换分支、同步 main 都等用户同意后再做：

```bash
git -C ~/kie-ws/<仓库名>/source status --short --branch
git -C ~/kie-ws/<仓库名>/source fetch origin
git -C ~/kie-ws/<仓库名>/source rev-list --count main..origin/main
```

报告内容：仓库在不在、当前分支、有没有未提交的改动、main 落后 `origin/main` 几个 commit。用户同意后按情况处理：

| 情况 | 用户同意后的做法 |
| --- | --- |
| 目录不存在 | 克隆到 `~/kie-ws/<仓库名>/source`，父目录不存在先建；用 `git clone <地址> <路径>`，或按 owner/repo 用 `gh repo clone <owner>/<仓库名> <路径>` |
| 在 main 上、工作区干净、main 落后 | `git merge --ff-only origin/main`，落后的 commit 数写进「项目现状」 |
| 停在别的分支，或有未提交改动 | 不切换、不清理；要看 main 上的实现用 `git show origin/main:<文件>` |

一份克隆服务调研、设计与后续工作区，不重复克隆。

## 调研

先调研再给方案，需求再小也不跳过。

| 需求 | 手段 |
| --- | --- |
| 网页、官方文档、社区讨论 | 网页搜索找入口，再读完整页面；用户给了链接就先把链接内容读完 |
| 库与框架的 API | 会话里有 context7 就用它查，没有就读官方文档与本地依赖源码（Rust 依赖在 `~/.cargo/registry/src/`） |
| 学术文献 | `paper-search search "<关键词>"` |
| 同类项目、issue 与 PR | `gh search repos`、`gh search code`、`gh issue view`、`gh pr view` |
| 已有工程的实现 | 读相关模块；有语言服务器时用它查引用，确定受影响的调用点 |

调研结论要落到事实：库名与版本、API 签名与前置条件、性能与限制、许可协议、最近的活跃程度。拿不准的写明不确定在哪，不猜，不编造参考文献。

## 选型文档 `solution.md`

写到 `~/kie-ws/<仓库名>/<name>/solution.md`，目录不存在就创建，只写自己工作目录下的文档，不动同级其他工作目录。章节、顺序与填写要求按 [assets/solution.md](assets/solution.md) 的模板来。

写完把文件路径与方案摘要给用户，请用户从中选定一个方案，不替用户选；需要用户补充的细节可以一并列出，但不代替选方案这一问。用户对方案有意见时，改 `solution.md` 里对应方案的描述，再交用户审核；已记录拍板方向的，同步更新拍板方向。

## 记录拍板

1. 在 `solution.md` 选中方案的标题处加标记，如 `## 方案二：<名称>（已选定）`，保留未选中的方案作为取舍记录。
2. 在文档的「拍板方向」中记录选定方案的关键形态与边界、涉及环节、风险与前置条件，以及其他方案不选的原因；只记录用户确认的信息。
3. 写完把 `solution.md` 路径给用户确认。
