## 填写要求

1. 逐节对照 `design.md` 把改动点映射成任务：

   | design.md 章节 | 计划里的对应 |
   | --- | --- |
   | 4. 详细设计 | 每处模块改动一个任务 |
   | 5. 接口变更清单 | 每个新增、修改、废弃的接口一个任务 |
   | 6. 兼容性与影响面 | 设计里写明要同步改动的使用方、CHANGELOG 条目、协议版本，各一个任务 |
   | 8. 测试用例 | 每个用例一条验收命令 |

2. 任务粒度取「能独立验证的一步」。任务顺序按依赖排：数据结构 → 接口 → 实现 → 调用方 → 测试 → 文档与配置。
3. 验收填可运行、能看出通过或失败的命令：单元测试跑具体用例、构建命令、CLI 实际调用、脚本检查。范围取改动涉及的最小粒度（单个用例、单个包、单个构建目标、单个文件），不写整仓命令，例如 Rust 的 `cargo test --workspace`。文档与配置类改动写具体观察方式（对比生成结果、检查渲染输出），不写「人工确认」。
4. 只写 `design.md` 里有的改动点，设计没写的不自行加进计划。
5. `plan.md` 每个任务目录只有一份。同一任务进入新一轮开发（设计文档出了新版本）时，把上一轮已全部勾选的任务整段移入「历史」，新计划写在上方。
