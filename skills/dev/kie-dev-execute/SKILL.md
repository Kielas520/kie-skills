# 按设计文档实现

读用户确认的设计文档，生成实现计划，逐条实现并验证到可运行状态。

产出物只有一份：`~/project/<项目名称>/.idea/plan.md`。技术方案与设计文档由 `kie-dev-design` 负责，本技能不改 `design.md` 的方案内容。

## 前置条件

`~/project/<项目名称>/.idea/design.md` 存在，且用户已确认。项目名以用户给的为准，用户没说就按当前工作目录的仓库名。

设计文档缺失或还没确认：说明情况并提示先走 `kie-dev-design`，不自行开始实现。

## 生成计划

读 `design.md` 全文，逐节对照，把设计里的改动点映射成任务：

| design.md 章节 | 计划里的对应 |
| --- | --- |
| 第 4 节 详细设计（仓 — 层 / 模块） | 每处模块改动一个任务 |
| 第 5 节 接口变更清单 | 每个新增、修改、废弃的接口一个任务 |
| 第 6 节 兼容性与影响面 | 需要同步改动的使用方、CHANGELOG、协议版本 |
| 第 8 节 测试用例 | 每个用例一条验收命令 |

任务粒度取「能独立验证的一步」。任务顺序按依赖排：数据结构 → 接口 → 实现 → 调用方 → 测试 → 文档与配置。

写入 `.idea/plan.md`：

```markdown
# <功能> 实现计划

设计文档：`.idea/design.md`

## 任务

- [ ] 1. <任务名>
  - 改动：`<文件>` / `<符号>`
  - 验收：`<命令>`

- [ ] 2. <任务名>
  - 改动：`<文件>` / `<符号>`
  - 验收：`<命令>`

## 历史

<上一轮开发已全部勾选的任务段，没有就删掉本节>
```

`plan.md` 固定单文件。同一项目进入新一轮开发（新的设计文档）时，把上一轮已全部勾选的任务整段移入「历史」段，新计划写在文件上方。

验收填写可运行、能看出通过或失败的命令：单元测试跑具体用例、构建命令、CLI 实际调用、脚本检查。文档与配置类改动写具体观察方式（例如对比生成结果、检查渲染输出），不写「人工确认」。

写完把 `plan.md` 路径告诉用户，接着开始执行，不停下来等审批。

## 执行循环

对每个未勾选任务：

1. 属于新增或修改行为的改动，先写测试并运行，看它失败。
2. 实现到测试通过。
3. 运行该任务的验收命令，看真实输出。
4. 验收通过，把 `- [ ]` 改成 `- [x]`，进入下一个任务。

仓库没有测试框架时，用最小可运行脚本或实际调用验证改动路径，脚本放在仓库内被忽略的目录，验证完删除。

命令失败、测试失败：读完整错误输出定位根因再改，禁止注释测试、放宽断言、跳过验收命令。定位手段用 `systematic-debugging`（若会话已装载该技能）。

实现与设计不符（设计里的签名不可行、依赖不存在、环境不具备）：暂停该任务，把设计写的是什么、实际遇到什么告诉用户，等用户决定。用户同意改设计时先更新 `design.md` 对应章节，再按新设计继续。

实现中发现设计漏写的改动点：补进 `plan.md` 再执行。

## 整体验证

全部任务勾选后：

1. 找项目定义的完整验证命令：读项目 `AGENTS.md`、`CLAUDE.md`、`README.md`、CI 配置（`.github/workflows/`）、`Makefile`、`scripts/` 下的检查脚本。找到就按适用范围执行（构建、测试、lint、格式、文档）。
2. 实际运行改变的功能：CLI 与脚本直接执行看输出，服务类启动后打真实请求，UI 用浏览器打开看界面，库类写临时脚本调用改动路径。观察到真实结果才算验证。
3. 无法在本机运行的场景（需要真实设备、外部服务）：说明缺什么前提，把已完成的验证范围写清楚。

汇报格式：

```text
━━━ 实现完成 ━━━
计划: ~/project/<项目>/.idea/plan.md（<n> 个任务全部勾选）
整体验证: <命令> 通过 / <命令> 通过
运行验证: <运行了什么、看到什么>
遗留: <未覆盖的问题，没有就省略本行>
```

## 硬性约束

- 不自动提交：`git add`、`commit`、`push` 只在用户明确要求时执行，格式按项目提交约定。
- 不改测试迁就实现：验收命令必须真实运行并看到输出，不接受「应该能过」的判断。
- 不扩范围：设计里没有的重构、额外错误处理、顺手加的抽象都不做。
- `plan.md` 的勾选是进度记录，完成与否以验收命令的输出为准。

## Gotchas

- `design.md` 可能在本轮开发中被用户改动，动手前重读受影响章节，不凭之前读到的内容写代码。
- 用户撤回已完成的改动时，按文件当前内容继续，不恢复被删除的内容；对应计划任务改回未勾选。
- `.idea/` 在部分项目里被 gitignore，`plan.md` 的历史段不能依赖 git 找回，全部勾选的任务留在文件里。
- 验收命令选具体范围（单个测试、单个 crate、单个文件）而不是整仓全量，保证每个任务的验证耗时可控；整体验证阶段才跑全量。
- 计划里任务的执行顺序与依赖不符时（后一个任务的前置没做），调整顺序并在 `plan.md` 里改过来，不硬按原顺序执行。
