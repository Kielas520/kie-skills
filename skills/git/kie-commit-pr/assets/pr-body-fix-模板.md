## 填写要求

1. 问题：先写关联工作项链接，无工单写「无关联工单」；再写现象、触发条件、出错信息原文、运行环境与版本，截图、日志、dump 放在这一段。
2. 原因：写到根因与机制；没定位就写「根因未定位，本次规避：…」。
3. 改动：按实际改动写行为上变了什么，不复制工单原文当作变更内容。
4. 验证：引用最近一次本地测试报告的结果，写同条件下的改前结果与改后结果、测试名和数量、运行环境；报告里没有的信息不补造。起草时不写远端 CI 结果，远端验收后再追加在本地结果下面。
5. 影响：需要回退的临时缓解、兼容性、回滚方式；没有内容就删掉这一段。
6. footer：`Resolve f-{ID}`；一次解决多个单写 `Resolve m-123, f-456`。
7. 一个 PR 一个工单一个主题。评审修复的往来与回复留在评论里，不写进描述；代码变化让改动、影响两段失实时同步更新。
8. 关联工单链接由用户给出，或从工单读取；取不到就问用户，不编造。
