## 填写要求

1. 背景：先写关联工作项链接，无工单写「无关联工单」；再写需求背景与设计文档路径。
2. 改动：按实际改动写行为上新增了什么，含资源名、命令、参数、默认值；不复制工单原文当作变更内容。
3. 验证：引用最近一次本地测试报告的结果，写测试名和数量与运行环境。起草时不写远端 CI 结果，远端验收后再追加在本地结果下面。
4. 影响：配套升级的组件和版本、默认行为变化；没有内容就删掉这一段。
5. footer：`Resolve m-{ID}`；一次解决多个单写 `Resolve m-123, f-456`；没有工单的 `chore` / `docs` / `ci` 省略 footer。
6. 一个 PR 一个工单一个主题。评审修复的往来与回复留在评论里，不写进描述；代码变化让改动、影响两段失实时同步更新。
7. 关联工单链接与设计文档链接由用户给出，或从工单读取；取不到就问用户，不编造。
