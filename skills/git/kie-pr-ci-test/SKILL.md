# PR 远端产物验收

PR 推送之后验收 CI 构建出来的远端产物，把结果并进本地测试报告，起草评论并更新 PR body。`<项目名称>` 与 `<任务>` 的取值、中间结果的落点见 `kie-agent-rules` 技能目录下的 `references/workspace.md`。命令清单见 [references/gh-ci.md](references/gh-ci.md)。

## 子能力

| 子能力 | 产出 | 何时做 |
| --- | --- | --- |
| 检查 CI 与说明验收范围 | CI 检查结果；这次验哪些验收标准、哪些 CI 产物、怎么验证 | 用户要求做远端验收时 |
| 下载产物并验收 | 每条验收标准在 CI 产物上的实际结果；缺陷单的对照实验结果 | 用户确认验收范围后 |
| 写远端结果 | 本地测试报告里的「远端 CI 结果」一节 | 验收完成后，用户确认结果内容后写入 |
| 发布评论 | PR 上的验收评论 | 用户确认评论内容后 |
| 更新 PR body | PR body 验证段里追加的远端结果 | 用户确认改好的 body 后 |

验收范围说明完后停下来，用户确认后才下载产物、开始验收。之后每一步也都等用户确认再进行。

## 验收依据

- 工单的内容与验收标准、缺陷单里的有问题版本：由用户给出，或从工单读取；取不到就问用户。
- 本地测试报告：在同一任务目录下找 `.idea/<任务>/test-report.md`。找不到时问用户，是先补本地测试，还是这次只做远端验收、新建报告。

## 检查 CI 与说明验收范围

CI 还在跑就先等结束：

```bash
gh pr checks <pr> --watch --interval 30
gh pr view <pr> --json statusCheckRollup \
  --jq '.statusCheckRollup[] | {name, status, conclusion, detailsUrl}'
```

检查项有失败或取消的，把失败项与链接报给用户，由用户决定先修还是继续验，不自行修改代码绕过检查。

CI 检查完后说明验收范围：逐条列出工单的验收标准与对应的 CI 产物、验证方式，说明有没有真实设备（见下一节），缺陷单说明用哪个有问题版本做对照。

## 真实设备

验收前先检索有没有可用的真实设备，检索方式按项目 `AGENTS.md` 写的来，没写就问用户。

- 有真实设备：涉及设备的验收标准必须在真机上用 CI 产物测。
- 没有真实设备：可以用 mock 代替，在远端结果的「远端未覆盖」里写明真机没有测、影响是什么。

## 下载产物并验收

```bash
gh run list --branch <分支名> --json databaseId,name,status,conclusion,url -L 10
gh run download <run-id> -n <artifact 名称> -D <中间结果落点>/ci-<run-id>/
```

1. 逐条过工单的验收标准，本机能跑的都在下载下来的 CI 产物上跑一遍。远端产物要真下载下来跑，脚本与结果都来自实际执行。
2. 缺陷单做对照实验：
   1. 取出工单里记录的有问题版本（tag、commit、安装包、固件版本），按工单描述的环境与步骤复现，确认问题确实出现。
   2. 用 CI 产物跑同样的步骤，确认问题不再出现。
   3. 两边的现象与输出并列记录，环境对不齐的部分写明差异。复现不出问题时按实际现象记录，交用户判断。
3. 远端产物跑不起来（缺少依赖、平台不符）时，写清缺什么前提，不拿 CI 绿灯代替验收。

产物验完移进回收站。

## 写远端结果、发布评论、更新 PR body

1. 按 [assets/远端CI结果.md](assets/远端CI结果.md) 的格式与「填写要求」写出远端结果给用户看。用户确认后，写进本地测试报告的「远端 CI 结果」一节，报告其他章节不动。
2. 起草 PR 评论：测了哪些验收标准、结论、CI 产物链接，缺陷单附有问题版本 tag。用户确认后才发布：

   ```bash
   gh pr comment <pr> --body-file <评论文件>
   ```

3. 更新 PR body：取出当前 body，在「验证」段原有的本地测试结果下面追加远端结果，本地部分与其他段都不动。改好的文件交用户确认后再写回：

   ```bash
   gh pr view <pr> --json body --jq .body > <body 文件>
   gh pr edit <pr> --body-file <改好的 body 文件>
   ```

## 交付

```text
━━━ PR 远端验收完成 ━━━
PR: {链接}
CI: {通过数}/{总数}
产物: {CI 产物链接}
有问题版本: {tag，缺陷单才写}
报告: ~/kie-ws/<项目名称>-p/.idea/<任务>/test-report.md
评论: {已发布 / 待用户确认}
PR body: {已追加远端结果 / 无需变更}
```

## Gotchas

- CI 通过只说明构建成功，验收标准仍要逐条过，绿灯不等于交付合格。
- 有的 `gh` 版本里 `gh pr checks` 不支持 `--json`，结构化状态统一用 `gh pr view --json statusCheckRollup` 取。
