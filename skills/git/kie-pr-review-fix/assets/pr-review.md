## 填写要求

1. 「问题清单」覆盖三类载体里的全部意见：未解决的 review threads、review body、会话区的 issue comments，一条意见一行。
2. 「状态」结合当前代码判断：已经解决；需要解决；不需要改。「不需要改」的在「说明」里写明理由：超出改动范围、与项目约定冲突，或意见本身不成立。
3. 机器人提出的建议也要先在代码里验证技术上是否合理，不因为来源是机器人就直接采纳或忽略。
4. 「解决方案」只给「需要解决」的问题写，改动的文件与符号写到符号一级。
5. 方案排序：先按收益从高到低，收益相同的再按改动量从小到大。
